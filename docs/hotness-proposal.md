# 熱度計算與資料流程（已實作）

採用討論後版本，取代先前提案中的 N−1、連續加成及額外退燒係數。

## 每日熱度

使用既有同行合併規則：同鳥點、完整時間、鳥種數相同。組內按非空顯示名稱去重，n 人的有效人次為 `1 + 0.5 × (n − 1)`；每人分得該值除以 n。同人同地同日多次出現，僅保留其最高一次貢獻，最後加總。

一人／二人／五人／十人同行分別為 1／1.5／3／5.5。兩人同行各 0.75；其中一人另外單獨到訪，其當日貢獻改為 1，因此總數為 1.75。

缺顯示名稱不虛構不同人數，當日標記不完整。同名不同人可能低估；名稱變更可能影響識別。同行判斷是近似，不代表確定為事先安排的鳥聚。

## 排序與展示

截至最後日期的最近三個已結束日，以 50%、30%、20% 加權。最後日期為今天則從昨天起算；歷史日包含該日。今日不計分，也不加連續到訪加成或額外降溫處罰。資料完整的分數優先降冪排序，資料不足排後；同分按地點 ID 固定排序。

展示天數只決定候選鳥點和清單明細，固定的分數不隨展示天數改變。每日曲線固定為截至最後日期的 14 天，獨立使用摘要。各曲線零起點、各自最高值標於右上，避免把曲線高度當作跨鳥點絕對值。

## 摘要與品質

`scripts/summaries.mjs` 從每份 snapshot 建立同日期 `summaries/YYYY-MM-DD.json`。欄位含算法版本、原資料更新時間、各縣市品質，以及按鳥點的 heat、people、checklists、unknown、regions。只統計觀察日期符合該日的清單，同 ID 跨縣市去重，不在摘要保留人名。

所有請求成功後 collect 重建摘要，build 也會重建以修正舊資料及算法更新。Actions 既有的 data commit 會涵蓋摘要。舊精簡 snapshot 保留，將來可重新計算。

縣市品質：complete（非上限且日結後已更新）、capped（至少 200 筆）、open（日結前擷取）、legacy（舊快照或無覆蓋資訊）。這裡 complete 只代表已取得 feed 未見截斷，並不保證日後沒有補登。

曲線中有資料的不完整值用空心點、相鄰線虛線；缺日／受截斷且沒出現的鳥點為未知，用斷線，不能補零。完整縣市未出現該鳥點才算零。任何評分日缺漏、未完整或含未知鳥友時顯示「資料不足」，不捏造可比較的分數。

網站不從曲線推斷特殊鳥種必定出現或離開。較平常升溫、週末校正、長期基準尚未加入本版。
